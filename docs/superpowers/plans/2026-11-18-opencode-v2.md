# Move pergent to opencode 2: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** pergent runs every review mode on opencode 2.3.2 with an allow-list sandbox, a private server per run, opencode 2's error format, and tests that run the real binary.

**Architecture:** The runner (`internal/runner`) and the config generator (`internal/config/opencode.go`) carry almost all the change: new flags and env for each run, an allow-list permission block, a new error parser and a startup version check. A new opt-in end-to-end test suite in `cmd/` runs `pergent agent` against the real opencode and a fake model server in Go, and a new CI workflow runs it on every PR.

**Tech Stack:** Go 1.24, opencode 2.3.2, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-18-opencode-v2-design.md` (sections are cited as "spec §N").

## Global Constraints

- Pinned and minimum opencode version: `2.3.2`. A newer version is allowed with a warning; an older or unparseable one is refused.
- Linux asset digests (sha256): x64 `563b5d663637226b6e3bb4bb6803281bc39b0d2cd88db06d674b6420aab009b0`, arm64 `9d10185acdb72336e086e699ca363a6065f410fd3c1caed0dc8046e95ac06ccb`.
- No support for opencode 1.x anywhere: no version branches, no 1.x error shape.
- A run pergent can't classify is a failure (`opencode_error`), never a pass.
- Temp directory prefixes for a run must not start with `pergent-` (the `external_directory` allow covers `pergent-*`).
- No change to the JSON result schema, the comment format or pergent.sh.
- Public repo: run `git grep -niE 'golabs|gojek|gopay[^t]|goto\b' -- . ':!go.sum' ':!docs/superpowers/plans/*'` before every commit; it must print nothing. No em dashes in new prose.
- No `docker`, no push, no release. Downloads of opencode binaries need the owner's OK. A darwin-arm64 2.3.2 binary is already downloaded locally.
- Commits: conventional subjects, ending with `Co-Authored-By: Claude <model> <noreply@anthropic.com>`.
- Verify: `make test`, `make vet`, `gofmt -l .` empty, and the e2e suite with `PERGENT_TEST_OPENCODE` set.

## Review Focus

1. **An error event followed by a normal-looking answer.** opencode 2 reports a provider error and then emits a step with text. The run must stay failed. Pinned by `TestParseOutput_ErrorThenTextStaysFailed` (Task 4).
2. **Version output with extra text.** Expect lines like `opencode v2.4.0-beta.2`, a trailing newline, or an update notice on another line. The check takes the first `vX.Y.Z` or `X.Y.Z` it finds and ignores a pre-release suffix. With no version at all it refuses. Pinned by `TestCheckVersionOutput` cases (Task 5).
3. **A long tool result saved to `tool-output`.** The model is pointed at the saved file. If 2.x moved that folder, the read is denied and the review quietly loses context. Pinned by `TestOpencodeE2E_LongToolOutputIsReadable` (Task 7).
4. **Own-config mode on 2.x.** No generated config, the user's global config instead. `--standalone` must still work and must not add the generated-config env. Pinned by `TestOpencodeE2E_OwnConfigMode` (Task 3).
5. **An impact run reading a linked clone.** The `external_directory` allows for clones, plus `Transcript.Opened` without the `list` tool. Pinned by `TestOpencodeE2E_ImpactRunRecordsOpenedClone` (Task 6).

- [ ] **Step 1: Write `newFakeModel`.** Port the scripted server the spike used. It answers `GET /v1/models` and streamed `POST /v1/chat/completions`.

  - **Requests without tools** (opencode's title agent) always get plain text.
  - **Call IDs are unique per turn** (`call_<turn>_<i>`). Reusing IDs across turns mislabels results.
  - **Modes:** `error500` answers 500 with `{"error":{"message":"mock internal error","type":"server_error"}}`. `overflow` answers 400 with the OpenAI `context_length_exceeded` body the spike used. `hang` never answers until the request's context ends.

  - It copies the binary to `t.TempDir()/bin/opencode`, so `pgrep -f` can find this test's processes and no others, and prepends that `bin` to `PATH`.
  - It sets `HOME`, `XDG_CONFIG_HOME` and `TMPDIR` to fresh temp directories.
  - It sets `OPENCODE_PROVIDER=fake`, `OPENCODE_MODEL=fake-model`, `OPENCODE_NPM=@ai-sdk/openai-compatible`, `OPENCODE_BASE_URL=<fake>/v1` and `OPENCODE_API_KEY=e2e-dummy-key`. Use `t.Setenv`: the runner reads the real environment.
- [ ] **Step 3: Write `runAgentE2E`.**
  - It calls `runAgent` with `--repo-path`, `--base`, `--head`, a one-skill `--skills-dir`, `--context-limit 100000`, `--concurrency 1`, `--timeout 3m`, `--result <file>` and `extraArgs`. It uses the real `review.Run` and returns the parsed result and stderr.
  - `e2eRepo` builds a git repo with `files` committed in the head commit only, and refuses a `HOME`-relative path.
- [ ] **Step 4: Write `TestOpencodeE2E_OffersOnlyReadTools`.** One turn with no tool calls. Assert that the tool names in the first request that has tools are a subset of `{"read","glob","grep","skill"}` and contain `read`, `glob` and `grep`.
